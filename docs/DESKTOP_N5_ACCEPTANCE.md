# Desktop-N5 发布验收

前提：N0–N4 已按顺序提交；Windows Desktop/SDK 0.2.1-rc.3，协议 1，Schema 7。不得使用 Subagent。

## 预先固定的真实预算

沿用 N2 总上限 6 次 SDK 活动（已消费 2 次：401 失败 1、A 完成 1）。N5 剩余最多 4 次：B 定向回复 1 次、A→B→A 讨论 3 次；以讨论中的根会话恢复替代原先可选的额外连续输入，聚合限额不增加。每次输入预留 32768、输出 768 tokens、估算费用 0.25 项目单位、60 秒。总计最多输入 196608、输出 4608、费用预留 1.5。新真实观察窗口最多 15 分钟；安装/离线验证时间不充作长稳时长。失败/未知不盲重试，不退还预算。

只在专用 native-dev 验收实例注入两条人工审阅的合成私有 Identity，绝不向模型透露对端标记。公开证据仅记录隔离布尔检查，不包含私有身份正文、Prompt 或 SDK 原始日志。

## 逐项门禁

1. 完整包新目录 npm ci 安装、原生发现双节点，未授权零调用（N4 实测）。
2. A/B 定向输入来自实际固定根，正式回复关联真实输入与完成 turn；检查独立 SDK 证明。
3. 重复点击/响应丢失/刷新/关闭重开/宿主重启无额外调用；实例切换不重定向旧请求。
4. 三轮讨论显示两个方向，达到预算停止；暂停/恢复不重置额度，旧 epoch 结果不产生效果。
5. SDK/服务损失、遗留锁、未知证明均可诊断，保留屏障并显式恢复（故障注入与 N3 真实实例记录）。
6. 成套备份/原位恢复保留根会话、幂等记录与预算（N3 实测），卸载/重装保留逻辑快照。
7. 私有身份未进入对端 Prompt/输出；脚本消息为文本，发送者/路径/管理权限伪造失败。
8. 形成最终源码包、支持矩阵、用户手册、分项证据与残留限制；提交并同步 GitHub。
