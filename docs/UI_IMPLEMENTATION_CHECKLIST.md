## 目标

提供一个独立的 DMN 界面，让用户直观看到两个不同的独立智能体，并能选择其中一个发送消息、查看该智能体的回复。两个智能体继续使用各自固定的 DSH 根 Session 和私有记忆，通过已有消息网关、持久队列与调度器运行。

DSH 继续作为模型运行底座；保留 Desktop/MCP。P4 采用回环本地 Web，不修改 DSH 核心；playwright-core 仅供验收使用。

## 第一版画面与交互

- [x] 为两个智能体各提供固定展示区域，包含头像或标识、名称、模型和简短职责；名称与标识应足以区分身份。
- [x] 显示各自真实状态：等待、排队、运行、退避、异常隔离；“已接收”不能显示成“模型已回复”。
- [x] 为用户提供明确的收件人选择，例如“发给 DeepSeek”或“发给 Reviewer”，发送前可清楚看到当前目标。
- [x] 提供输入框、发送按钮、发送中反馈、持久化接收确认和可理解的失败提示。
- [x] 分别呈现用户与各智能体的交流记录；切换选中智能体后仍能找到原记录。
- [x] 将 `用户 → A`、`A → 用户`、`A → B`、`B → A` 明确区分，展示收发双方、正文、时间及处理状态。
- [x] 如果展示节点间讨论，提供可回看的消息时间线；节点间消息与面向用户的回复使用不同方向标识。
- [x] 动画仅反映真实状态变化；等待、静默、拒绝和异常均有准确表达，不用持续动画假装正在交流。
- [x] 明确显示当前话题、已用轮数、额度和截止时间，并提供暂停、恢复、结束操作及执行结果。
- [x] 展示空状态、加载状态、服务断开和预算耗尽状态；不能因刷新页面自动创建或恢复话题。

## 消息语义与服务端契约先行

- [x] 定义用户定向发消息与允许节点间自主讨论的区别。用户发给 A 的消息默认只投递给 A，不隐式广播给 B。
- [x] 创建话题或开启节点间讨论必须来自明确用户操作，并展示有限预算；不能由节点消息、页面加载或动画触发授权。
- [x] 定义并实现“智能体回复用户”的受控输出及持久化契约。新增 `reply_user`、正式回复存储及关联查询，不将入队确认当作一对一回复。
- [x] 面向用户的回复必须与实际输入、节点身份及完成回执关联，支持刷新后恢复和幂等去重，不能直接展示私有 Prompt、推理内容或完整 SDK 历史充当回复。
- [x] 身份从可信宿主上下文绑定；界面与模型不能通过 `from`、Session ID 或记忆 owner 参数冒充另一个节点。
- [x] 复用已有网关、预算、队列、锁和对账规则；前端不能直接访问数据库或绕过宿主校验。
- [x] 如果新增本地管理服务，先设计访问认证、来源校验及安全默认值；不默认开放远程访问。
- [x] 若需扩展数据库，先提供迁移、回滚/备份说明及恢复测试；保留现有 Desktop/MCP 契约的兼容性。

## 独立性与权限边界

- [x] 两个节点仍为独立根 Session，不引入 Subagent、父子代理关系或同节点并行调用。
- [x] UI 中的智能体身份、会话与后台节点一一对应；刷新、切换视图或重连不新建节点根会话。
- [x] 用户发给 A 的消息及 A 的私有记忆不能因共享画面自动进入 B 的输入；允许共享的节点消息仍需经过消息总线。
- [x] 模型节点不获得 UI 管理、任意 Shell、文件写入、其他节点记忆或扩大预算的权限。
- [x] 消息正文作为不可信数据渲染，不执行 HTML、脚本、命令或伪造管理指令。
- [x] 继续严格拒绝非法模型输出；将当前长对话 JSON 格式不稳定问题作为依赖风险记录，不能通过隐藏失败或无限重试掩盖。

## 第一版不包含

- 第三节点、跨 Provider 扩展及完整生产部署。
- 3D 场景、复杂角色动画、语音对话或桌宠系统。
- 跨节点私有记忆浏览器、完整 SDK 历史展示或任意工具权限配置。
- 自动重置预算、自动新建话题续聊、自动删除锁或重放未知执行结果。

## 验收清单

- [x] 页面能清楚辨认两个不同智能体及各自状态；没有用同一个模型输出伪装两人对话。
- [x] 用户选择 A 发送一条消息：只有 A 收到该输入，返回的可见回复明确来自 A。
- [x] 用户选择 B 发送另一条消息：只有 B 收到该输入，返回的可见回复明确来自 B。
- [x] 两次交互使用各自原有根 Session，并验证输入和私有记忆没有串线。
- [x] 在明确授权的讨论中，A→B 与 B→A 的消息方向、真实投递和完成状态可见。
- [x] 重复点击、网络重试和页面刷新不会重复入队、重复调用模型或丢失已确认消息。
- [x] 暂停、恢复、关闭及预算停止与后台状态一致；旧回合不能在暂停后越权产生新消息。
- [x] 失败、静默、断开与未知结果均可辨认，界面不会将 Accepted 或 SDK 回执误报为完整回复。
- [x] 完成真实浏览器操作验证、真实双节点消息验证与故障恢复验证，并记录 PASS / FAIL / NOT_RUN。
