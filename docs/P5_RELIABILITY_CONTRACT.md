# P5 可靠运行与恢复契约

本阶段仅加固两个既有独立根节点，不增加模型权限或自动化授权；无新数据库字段，沿用 v7。实施顺序：本契约、测试、维护/持久化边界、恢复与查询、管理入口、验收。当前为实施契约，完成情况另见阶段报告。

## 恢复

- 只读检查返回可信轮次/节点/话题、锁、尝试与完成证明类别，不返回 Prompt、输出原文、私有记忆或凭据，不调用模型。
- 过期运行租约只能转 unknown + quarantined，不重排、不释放隔离锁、不删除 Runtime marker。
- inspect 对账只使用已有完整 SDK 证明或检查点。未知证据继续隔离，已确认非法输出转死信。
- 人工 drop 仅在底层确认 Runtime 静止后生效；CLI 要求确认准确 turnId 和非空原因，固定 operator 身份写审计。同一轮次重复处理不重复效果，不重置预算。

## 停机成套备份

- 主数据库与 `<db>.runtime` 属于同一恢复单元。所有新版 DmnStore 实例登记进程租约，与备份/恢复共享短暂文件屏障；备份仅在无活跃实例、无运行轮次和无 Runtime marker 时进行。
- 仅确认 PID 不存在的宿主进程登记可以清理。Runtime marker 或维护屏障遗留不自动删除；PID 复用/不明进程均保守阻塞。旧版进程不具备登记能力，必须由操作者确认全部退出。
- SQLite 官方 backup API 生成含 WAL 已提交内容的一致快照；Runtime 文件逐一复制与 SHA-256 校验。拒绝符号链接、路径穿越、覆盖目标、自包含备份与不兼容版本。完成前目录为 partial，最后原子发布 manifest 完整的成品目录。
- 恢复校验完整文件清单、哈希、版本、SQLite 完整性及外键。只恢复到 manifest 记录的原始绝对数据库位置，且数据库、WAL/SHM、Runtime 均不存在；不覆盖数据，不改写 SDK 日志中的 cwd/Session ID。需要迁移目录时另行设计，不假装支持。
- 恢复提交途中失败保留 incomplete 标记并阻止 DmnStore 启动，不能把不完整的一对文件当作成功。备份含私有记忆/Session 历史，属于敏感本地数据，不上传 GitHub。

## 查询与指标

- 追加 cursor/limit 查询，按 SQLite rowid keyset 分页；固定每类 high-water，后续新增记录不混进该次翻页。旧 get_messages 的三个数组仍保留，增加 page 元数据；状态可反映后续完成，正文及 ID 不变。
- 指标区分队列深度、排队等待、执行耗时、失败/未知/重试尝试、预算预留与有 SDK 用量证明的实际 Token。无 actual 记录不得补零伪装完整；不编造实际账单。
- 管理查询不提供跨节点私有记忆；所有新参数严格验证。读取不唤醒节点，分页不能改变参与者/预算。
- 运行数据默认完整保留，无自动删库、清锁、清审计或裁剪 SDK 历史。磁盘保留策略与离线归档流程写操作手册；记忆删除规则留 P7。

## 验收

故障注入须覆盖崩溃、数据库重开/结果提交失败、超时、重复请求、伪造身份/提示注入、过期租约、遗留 marker；演练含私有记忆与双根历史的成套备份、校验、原位恢复和恢复后不重复执行。真实模型验收预设最多 4 次、131072 输入/4096 输出 Token、估算 $1；备份/恢复本身不调用模型。长时间运行限定时长、请求数与故障点，报告实际观测范围，不宣称任意故障自愈。
